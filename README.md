# persona-mining · 抖音电商「挖掘人群」Skill（S2）

> 抖音电商内容策略 Skill 组的第二步：把一份买点库，变成一份**带优先级、经抖音内容侧验证过的人群匹配表**。
> 人群从买点倒推、不拍脑袋，并通过抖音真实内容验证人群是否存在。

---

## 它解决什么问题

做抖音内容最常踩的坑：人群写得太宽——"18–35 岁女性"。这种画像没法拍、没法定向、没法排优先级。

这个 skill 做三件事：

1. **从买点倒推人群**：不是先画 demographic 再套卖点，而是问"谁最需要这个收益"。
2. **用抖音内容侧验证**：这群人在抖音上是不是真的存在？有没有专门内容、互动量多大？纯推测的人群会被降级或淘汰。
3. **收敛成可执行的卡片**：3–4 张主攻人群卡，每张都能直接指导第一条视频拍给谁看、用什么话术、打什么标签。

## 在 Skill 组里的位置

```
S1 sell-point-to-buy-point（卖点转买点）
        │  输出：买点库 HTML（每条买点 = 收益/证据/可展示角度/Tier）
        ▼

        │  输出：人群匹配表 HTML（主攻/可测试/叠加）
        ▼

```

## 输入与输出

| | 内容 |
|---|---|
| **输入** | S1 产出的买点库（HTML 报告路径/链接，或直接粘贴买点清单） |
| **只吃** | Tier 1 / Tier 2 买点（Tier 3 信任底座不单独生成人群） |
| **输出** | 人群匹配表 HTML 报告（一屏扫完，给商家没有阅读压力） |

## 四步流程

1. **倒推人群**——对每个 Tier1/2 买点反向问"谁最需要这个？谁在这个痛点上最强？"
2. **画像立起来**——年龄区间 + 身份/生活状态 + 兴趣爱好（他们刷什么、信什么、买东西看什么）。区间即可，**不编造化名人物**。
3. **内容侧核验**——调用 `video_search` 看这群人在抖音是否真实活跃、有无专门内容、互动量多少。
4. **打分排序**——三维打分（卖点匹配 / 付费意愿 / 人群规模，1–10），定结论：**主攻 / 可测试 / 叠加**，收敛到 4 张主攻卡。

## 人群卡固定四行

每张卡扫一眼读完：

- **画像**：区间 / 身份 / 生活状态 / 兴趣爱好
- **心理**：痛点 / 决策动机 / 顾虑（顾虑对应内容侧负面信号）
- **打动**：用哪个买点、什么表达角度（一句话落到话术）
- **触达**：内容形态 + 话题标签

外加一行 `✓ 已验证`（内容侧信号收敛成一行，含典型视频标题+互动量，不展开大段证据）和打分条。

## 真实样例（4 个品类，已验证跨品类可靠）

打开 `persona-mining/assets/example/` 可直接看渲染效果：

| 样例 | 品类 | 人群驱动逻辑 |
|---|---|---|
| `camel-persona.html` | 服饰鞋包（骆驼女鞋） | 身份/穿搭驱动：小个子显高党、穿搭出片党 |
| `tuli-persona.html` | 家居清洁（马桶泡泡粉） | 生活状态/痛点驱动：合租尴尬党、下班懒人 |
| `bulamai-persona.html` | 出行耐用品（行李箱） | 功能+粉丝双轨：开学学生党 vs 王俊凯追星女孩 |
| `mcm-persona.html` | 轻奢悦己（波士顿包） | 身份仪式感：第一只大牌包入门人群 |

> 同一套四行版式，在四种完全不同的决策逻辑下人群画像会跟着买点自动变化、不套模板。

## 设计口径（写课程/复用时看这里）

- **人群从买点倒推，不从 demographic 套**：换品类后人群必须跟着买点变，禁止平移上一个商品的标签。
- **新发现人群是增量价值**：内容侧反复出现、但商品资料没覆盖的人群（如宽脚党、粉丝党），重点标注。
- **证据分来源**：本商品事实（来自商品资料）vs 抖音同品类内容（内容侧信号），不混读。
- **对外只交付运行样例（C 端 HTML），不交付 schema 和提示词。**
