# 挖掘人群（S2）

把买点库（sell-point-to-buy-point 的输出），转成一份带优先级的人群匹配表 HTML 报告。人群从买点倒推、不拍脑袋，并用抖音内容侧信号验证。输出供 S3 挖掘场景 / S4 组合报告直接消费。

## 输入

上一步 S1 产出的买点库文件（HTML 报告路径或链接，也可直接粘贴买点清单）。只消费 Tier 1 / Tier 2 买点做主攻；Tier 3 信任底座不单独生成人群。

## 执行流程（四步）

1. **倒推人群**——对每个 Tier 1/2 买点反向提问"谁最需要这个？谁在这个痛点上最强？"，生成候选人群。禁止先想"18-35 岁女生"这种宽泛区间再套卖点。
2. **画像立起来**——每个候选人群写清：年龄区间 + 身份/生活状态 + **兴趣与爱好**（刷什么内容、信什么、买东西看什么）。区间即可，**不编造具体化名人物**。
3. **内容侧核验**——调用 `video_search` 检索该人群是否在抖音真实活跃、有没有专门内容、互动量多少。有专门内容且有互动量 = 真实存在；纯推测 = 降级或淘汰。区分「独立强调」与「捆绑提及」（沿用 S1 口径）。
4. **打分排序 + 输出**——每个候选人群打三维分（卖点匹配度 / 付费意愿 / 人群规模，各 1-10），定结论：主攻 / 可测试 / 叠加。合并重复人群（一个人可能被多个买点覆盖），一般收敛到 4 张主攻卡 + 少量叠加。

完整提示词见 [references/prompts.md](references/prompts.md)，字段口径见 [references/schema.md](references/schema.md)。

## 人群卡必含四行（版式硬约束）

每张卡固定四行，扫一眼读完：

- **画像**：年龄区间 / 身份 / 生活状态 / 兴趣爱好（一行写完）
- **心理**：痛点强度 / 决策动机 / 顾虑（顾虑须对应内容侧负面信号）
- **打动**：用哪个买点、什么表达角度（一句话，落到具体话术）
- **触达**：内容形态 + 话题标签（怎么触达这群人）

外加一行 **✓ 已验证**（内容侧信号收敛成一行，含典型视频标题+互动量，不展开大段证据列表）和打分条。

## 内容侧核验要点

- 人群必须"真实存在"才算数：抖音上有专门面向这群人的内容、有互动量，才标 ✓ 已验证。
- 人群从买点倒推，不是从 demographic 套：同一个商品，换品类后人群画像要跟着买点变（例：服饰鞋包=身份/穿搭驱动，家居清洁=生活状态/痛点驱动），禁止把上一个商品的人群标签平移过来。
- 新发现人群：内容侧反复出现、但商品资料/买点没覆盖的人群（如宽脚党、合租党），重点标注——这是 skill 给商家的增量价值。
- 证据一律标注来源类型：本商品事实 vs 抖音同品类内容，不混读。

## 输出与交付

生成人群匹配表 HTML，结构与样式参照 [assets/report-template.html](assets/report-template.html)（骨架）和 [assets/example/](assets/example/)（四个跨品类真实样例）：

- `camel-persona.html` — 服饰鞋包（骆驼女鞋）：身份/穿搭驱动
- `tuli-persona.html` — 家居清洁（马桶泡泡粉）：生活状态/痛点驱动
- `bulamai-persona.html` — 出行耐用品（行李箱）：功能 + 粉丝双轨
- `mcm-persona.html` — 轻奢悦己（波士顿包）：第一只大牌包的身份仪式感

> 四个样例覆盖四种不同决策逻辑，验证同一套四行版式在跨品类时人群画像会跟着买点自动变化、不套模板。

- **Hero**：商品名、一句话策略（先打哪几个人群）
- **人群卡**：按主攻→可测试→叠加排列；每卡含画像/心理/打动/触达/✓已验证/打分
- **页脚**：资料来源 + 口径 + "由 persona-mining Skill 生成"

通过 `present_files` 交付 HTML 报告。对外只交付运行样例，不交付 schema 和提示词。
